# URL Shortener

Backend-сервис для сокращения ссылок с аналитикой переходов. Портфолио-проект, построенный с акцентом на продакшн-практики: кэширование, фоновую обработку, миграции и тесты.

## Возможности

- Сокращение длинных ссылок с автоматической дедупликацией (одна и та же ссылка не создаётся дважды)
- Редирект по короткому коду с подсчётом кликов
- Короткие коды генерируются на основе ID записи через Hashids — уникальны без коллизий, но не последовательны и не угадываются
- Redis-кэш для быстрых редиректов (cache-aside pattern)
- Подсчёт кликов асинхронно через FastAPI BackgroundTasks — не блокирует ответ пользователю
- Аналитика: разбивка кликов по дням и по типу устройства (desktop/mobile/tablet/bot)
- Простая HTML-страница со списком всех ссылок
- Полностью в Docker: Postgres + Redis + приложение одной командой

## Стек

- **FastAPI** — веб-фреймворк
- **PostgreSQL** + **SQLAlchemy 2.0 (async)** — база данных
- **Alembic** — миграции
- **Redis** — кэширование
- **Hashids** — генерация коротких кодов
- **Jinja2** — HTML-шаблоны
- **pytest** + **httpx** — тестирование
- **Docker / docker-compose** — контейнеризация

## Запуск

### Через Docker (рекомендуется)

```bash
docker-compose up --build
```

Затем примени миграции:

```bash
docker-compose exec api alembic upgrade head
```

Приложение будет доступно на `http://localhost:8000`.

### Локально (без Docker)

1. Создай виртуальное окружение и установи зависимости:
```bash
   python -m venv venv
   venv\Scripts\activate  # Windows
   pip install -r requirements.txt
```
2. Создай базу данных `url_shortener` в PostgreSQL и запусти Redis.
3. Скопируй `.env.example` в `.env` и заполни переменные.
4. Примени миграции: `alembic upgrade head`
5. Запусти сервер: `uvicorn main:app --reload`

## API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/shorten` | Создать короткую ссылку (`{"long_url": "..."}`) |
| `GET` | `/{code}` | Редирект на длинную ссылку |
| `GET` | `/{code}/stats` | Статистика: клики по дням и устройствам |
| `GET` | `/` | HTML-страница со списком всех ссылок |

Полная интерактивная документация — на `/docs` (Swagger UI).

## Архитектурные решения

- **Короткие коды через Hashids, а не случайную генерацию** — коды основаны на ID записи, что гарантирует уникальность без retry-логики, при этом остаются неугадываемыми благодаря "перемешиванию" через соль.
- **Cache-aside через Redis** — при переходе по ссылке сначала проверяется кэш; при промахе данные читаются из Postgres и кладутся в кэш с TTL.
- **BackgroundTasks для записи кликов** — редирект отдаётся пользователю сразу, подсчёт клика и запись в лог происходят после отправки ответа.
- **Дедупликация** — перед созданием новой записи проверяется, нет ли уже такого `long_url` в базе.

## Тесты

```bash
pytest -v
```

Тесты используют отдельную тестовую базу данных и изолированный Redis (очищается перед каждым тестом).
